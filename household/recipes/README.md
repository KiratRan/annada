# Recipe Library

This directory contains normalized household recipes in Markdown format.

Location:

```
$HOUSEHOLD_ROOT/recipes
```

The household-wide operating instructions are in:

```
$HOUSEHOLD_ROOT/ASSISTANT.md
```

Read that file for general behavior and file-safety rules.

This README defines the recipe-specific conventions.

---

# What belongs here

Store one complete normalized recipe per Markdown file.

Include:

- manually entered recipes
- website imports
- family recipes
- adapted recipes
- personal household recipes

Put raw webpages, screenshots, PDFs, and unprocessed text in:

```
$HOUSEHOLD_ROOT/recipe-imports
```

instead.

---

# Directory contents

The recipe library contains:

```
recipes/
├── README.md
├── index.yaml
└── recipe-name.md
```

## Recipe files

Individual Markdown recipe files are the source of truth.

They contain:

- recipe content
- ingredients
- instructions
- notes
- source attribution
- YAML frontmatter metadata

## Recipe index

The file:

```
$HOUSEHOLD_ROOT/recipes/index.yaml
```

is a generated recipe catalog.

It exists to allow agents to quickly search and rank recipes without parsing every recipe file.

The index is:

- generated from recipe Markdown files
- generated from YAML frontmatter
- not a source of truth
- safe to regenerate

Never manually edit `index.yaml`.

If information conflicts:

1. Recipe Markdown file
2. Recipe frontmatter
3. Recipe index

The Markdown recipe remains authoritative.

---

# File naming

Use lowercase, descriptive filenames with hyphens.

Examples:

```
chicken-rice-bowls.md
vegetable-lasagna.md
slow-cooker-beef-stew.md
```

Avoid:

- spaces
- special characters
- generic names
- duplicate filenames

Before creating a recipe:

1. Check existing filenames.
2. Check existing recipe titles.
3. Check for duplicate recipes.

Never overwrite an existing recipe without explicit approval.

---

# Recipe format

Recipes use Markdown with YAML frontmatter.

Frontmatter is machine-readable metadata generated by the recipe-library-manager skill.

The Markdown body remains the human-readable recipe source.

Example:

```markdown
---
id: slow-cooker-beef-stew

title: Slow Cooker Beef Stew

category:
  - Dinner

cuisine:
  - American

servings: 4

time:
  prep_minutes: 5
  cook_minutes: 25
  total_minutes: 30

difficulty: Easy

tags:
  - beef
  - soup

source:
  type: website
  url: https://example.com
  author: Author
  verification:
    status: verified
    method: direct_source
---

# Slow Cooker Beef Stew

## Ingredients

- Ingredient

## Instructions

1. Step

## Notes

Notes

## Source

Original:
https://example.com
```

---

# Frontmatter conventions

Frontmatter is maintained by the recipe-library-manager skill.

Use these fields when known.

## Identity

```yaml
id:
title:
```

The `id` must match the filename without `.md`.

Example:

File:

```
chicken-tikka-masala.md
```

Frontmatter:

```yaml
id: chicken-tikka-masala
```

---

## Classification

```yaml
category:
cuisine:
tags:
diet:
```

Do not invent classifications that are unsupported.

---

## Timing

```yaml
time:
  prep_minutes:
  cook_minutes:
  total_minutes:
```

Do not estimate missing times.

Use:

```yaml
Unknown
```

when unavailable.

---

## Servings

Preserve the original recipe serving count.

Do not scale recipes unless explicitly requested.

---

## Difficulty

Allowed values:

- Easy
- Moderate
- Difficult
- Unknown

Difficulty should not be invented.

---

## Source metadata

Every recipe must preserve source information.

Example:

```yaml
source:
  type: website
  url: https://example.com
  author: Unknown
  verification:
    status: verified
    method: direct_source
```

Verification methods:

- direct_source
- wayback_archive
- user_provided
- unknown

Never replace an original URL with an archive URL.

---

# Ingredients

The Markdown ingredient section is authoritative.

Rules:

- Preserve source quantities whenever available.
- Keep units consistent.
- List ingredients in practical usage order.
- Identify optional ingredients.
- Put substitutions in Notes unless they are part of the original recipe.
- Do not silently convert quantities.
- Do not invent missing quantities.

If unavailable:

```
quantity not specified
```

---

# Instructions

Rules:

- Use numbered steps.
- Preserve original order unless normalization is required.
- Preserve temperatures, timing, and safety instructions.
- Do not invent missing steps.
- Record incomplete information in Notes.

---

# Source and attribution

Always include:

```
## Source
```

Examples:

```markdown
## Source

Original recipe
```

or:

```markdown
## Source

Original:
https://example.com

Author:
Recipe author

Verification:
Direct source page accessed at import time.
```

For imports:

- preserve original URL
- preserve author when available
- record verification status
- distinguish direct access from archived access

# Recipe index generation

`index.yaml` is maintained automatically by the recipe-library-manager skill.

The index should contain:

- recipe ID
- title
- filename
- category
- cuisine
- tags
- timing
- servings
- normalized ingredient information when available

The index should not contain:

- full instructions
- duplicated recipe text
- unsupported metadata

Example:

```yaml
version: 1

generated_by:
  skill: recipe-library-manager

recipes:

  slow-cooker-beef-stew:
    title: Slow Cooker Beef Stew
    file: slow-cooker-beef-stew.md

    category:
      - Dinner

    cuisine:
      - American

    tags:
      - beef
      - stew

    time:
      total_minutes: 360

    servings: 6

    ingredients:
      - beef
      - carrots
      - potatoes
      - onion
```

# Import workflow

When importing a recipe:

1. Read source material.
2. Extract recipe information.
3. Check duplicates.
4. Normalize recipe content.
5. Generate YAML frontmatter.
6. Save recipe Markdown file.
7. Update `index.yaml`.
8. Verify files were written.
9. Report created paths and unknown information.

Do not save recipes from:

- titles only
- search snippets
- incomplete previews

unless explicitly requested as placeholders.

---

# Scaling recipes

When scaling recipes:

- preserve the original file
- create a separate copy when requested
- state original and new serving counts
- recalculate carefully
- flag non-linear ingredients
- do not overwrite originals

---

# Recipe quality checks

Before saving:

- title exists
- filename is unique
- frontmatter exists
- recipe ID matches filename
- ingredients exist
- instructions exist
- source is identified
- verification is accurate
- unsupported values are not added
